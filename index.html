1. Introduction, principle and objectives

The experiment measures ambient temperature and relative humidity using a digital sensor such as the DHT11 or DHT22 and displays the values on a 16×2 character LCD. The Raspberry Pi acts as the controller: it reads the sensor, formats the data, and updates the display.

Temperature

Indicates how hot or cold the surrounding environment is; commonly shown in degrees Celsius (°C).

Relative humidity

Amount of water vapour in air relative to saturation, expressed as a percentage (%RH).

LCD

A low-power character display. A 16×2 LCD can show 16 characters on each of two lines.

Operating principle

  1. The sensor measures temperature and humidity and provides a digital signal.
  2. Raspberry Pi GPIO receives the sensor data; a suitable software library decodes the sensor protocol.
  3. Python checks whether a valid reading was received and converts values into readable strings.
  4. The LCD receives commands and character data through an I²C backpack or parallel interface.
  5. The program refreshes the display periodically to show the latest valid values.
Important: Raspberry Pi GPIO is 3.3 V logic and is not 5 V tolerant. Never connect a 5 V signal directly to a GPIO pin. Use a compatible sensor/interface and verify the module's voltage requirements.

3. System block diagram

Signal flow

Physical quantity → sensor conversion → digital signal → Pi software → formatted text → LCD. The sensor and LCD use different interfaces: DHT data is a timed single-wire digital protocol, while the LCD backpack typically uses I²C.

4. Working procedure and engineering considerations

  1. Assemble the circuit with power disconnected. Verify pin labels and common ground.
  2. Enable I²C in the Raspberry Pi configuration if the LCD uses I²C; reboot if required.
  3. Install compatible Python packages for the chosen sensor and LCD backpack. Confirm library documentation for your OS version.
  4. Run an I²C scan to find the LCD address, if the platform provides i2cdetect.
  5. Read the sensor at its recommended interval. DHT sensors should not be polled continuously at very high rates; consult the datasheet/library.
  6. Handle failed or checksum-invalid reads. Preserve the last valid reading or display a clear error rather than showing fabricated values.
  7. Format output to fit 16 characters per line and refresh the LCD.

Advantages

  • Low-cost environmental monitoring.
  • Local, immediate visual feedback.
  • Useful for IoT prototypes and data-logging extensions.

Limitations

  • DHT sensor accuracy and response time are limited.
  • LCD character count constrains presentation.
  • Library compatibility can vary by OS and hardware revision.
  • Wiring mistakes and unsafe logic levels can damage GPIO.

Common misconceptions

  • GPIO numbering: BCM GPIO 4 is physical header pin 7, not physical pin 4.
  • I²C address: 0x27 is common, not guaranteed.
  • Voltage: a module being powered at 5 V does not mean its logic signals are safe for a Pi.
  • Humidity: %RH is not an absolute mass of water in air.

5. Example Python program

This is a teaching template for a Raspberry Pi, DHT22-style sensor library, and an I²C character LCD. Package names, class names, and LCD initialization differ across libraries; adapt the imports and constructor to the exact library installed. This page does not install packages or run hardware code.

# Illustrative template — adapt to the selected libraries
import time
import board
import adafruit_dht
from RPLCD.i2c import CharLCD

# Example: DHT22 data connected to BCM GPIO 4.
sensor = adafruit_dht.DHT22(board.D4)

# Change address to the address discovered on your hardware.
lcd = CharLCD('PCF8574', 0x27, port=1, cols=16, rows=2)

try:
    while True:
        try:
            temperature_c = sensor.temperature
            humidity_pct = sensor.humidity

            if temperature_c is None or humidity_pct is None:
                raise RuntimeError("No valid reading")

            line1 = f"Temp: {temperature_c:4.1f} C"
            line2 = f"Humidity:{humidity_pct:4.1f}%"
            lcd.clear()
            lcd.write_string(line1[:16].ljust(16))
            lcd.crlf()
            lcd.write_string(line2[:16].ljust(16))

        except (RuntimeError, OSError) as error:
            # Sensor read failures can be transient; do not invent readings.
            lcd.clear()
            lcd.write_string("Sensor read err")
            lcd.crlf()
            lcd.write_string("Retrying...")
        time.sleep(2)

finally:
    lcd.clear()
    sensor.exit()
Compatibility note: this combines commonly used library styles as an example, not a guaranteed drop-in program for every Raspberry Pi OS release. Check current library documentation, permissions, I²C setup, and the exact LCD backpack driver. Do not run without adapting it to the hardware.

Algorithm / pseudocode

INITIALIZE sensor, I2C bus and LCD
LOOP:
    read temperature and humidity
    IF reading is valid:
        format values for the two LCD rows
        write both rows
    ELSE:
        show a sensor error / retry message
    wait for the supported sampling interval
CLEAN UP on program exit

8. Core electronics / embedded interview preparation

1. Why use a Raspberry Pi for this experiment?

It is a Linux-capable single-board computer with GPIO and I²C interfaces, so it can read a sensor, run Python logic, and drive a display. A microcontroller could also perform the task with a different software environment.

2. What is the difference between GPIO and I²C?

GPIO is a general-purpose digital input/output pin interface. I²C is a synchronous two-wire serial bus using SDA and SCL, typically supporting multiple addressed devices on the same bus.

3. Why is a level shifter sometimes required for an LCD?

Some I²C backpacks pull SDA/SCL up to 5 V. Raspberry Pi GPIO is 3.3 V logic and not 5 V tolerant, so a suitable 3.3 V-compatible interface or bidirectional level shifter may be necessary.

4. What does relative humidity mean?

It is the ratio of actual water-vapour partial pressure to the saturation vapour pressure at the same temperature, expressed as a percentage.

5. Why can a DHT sensor read fail intermittently?

Possible causes include timing sensitivity, incorrect wiring, missing pull-up, power instability, reading too frequently, a poor connection, or library/OS compatibility. Check the datasheet and log errors before changing hardware.

6. Why use an I²C LCD backpack?

It reduces the number of Raspberry Pi pins needed compared with a typical parallel LCD interface, at the cost of an I²C controller/backpack and its driver requirements.

7. What is the purpose of a pull-up resistor on the sensor data line?

It holds the data line at a defined high logic level when no device is pulling it low. The required value and whether one is already fitted depend on the sensor module and interface.

8. How would you debug a blank LCD?

Check power, ground, contrast adjustment, wiring, I²C enabled state, detected address, backpack compatibility, library configuration, and whether the program reaches LCD initialization.

9. How do you make the program robust?

Validate readings, handle transient exceptions, avoid displaying invalid data as real, use a suitable sampling interval, keep strings within display width, and clean up hardware resources on exit.

10. Can Multisim directly simulate the entire Raspberry Pi Python program and DHT sensor?

Not typically as a complete native Raspberry Pi/Linux/Python execution environment. Multisim is primarily an electronic circuit simulator. Use a block/system diagram for the concept and test the actual GPIO software on a Pi or a compatible hardware/software emulator. Do not label a conceptual diagram as measured simulation output.

11. How could this become an IoT product?

Add periodic logging, a network transport such as MQTT or HTTPS, timestamps, calibration/quality checks, and a dashboard or alerting service. Secure credentials and design for reconnects and sensor faults.

12. What test cases would you include?

Normal readings, sensor disconnected, invalid checksum/read error, humidity boundary values, LCD address mismatch, power cycling, long-duration operation, and checking that displayed units and decimal formatting are correct.

11. Quick revision sheet

Important definitions

  • GPIO: configurable digital input/output pins on the controller.
  • I²C: two-wire serial bus with data (SDA) and clock (SCL).
  • 16×2 LCD: character display with 2 rows and 16 character positions per row.
  • Relative humidity: water-vapour partial pressure divided by saturation vapour pressure at the same temperature, multiplied by 100%.

Formula / calculation reminder

RH (%) = (actual water-vapour partial pressure / saturation vapour pressure at the same temperature) × 100%

This relationship defines relative humidity; in this experiment the digital sensor normally reports the temperature and RH directly, so the program does not need to calculate RH from raw physical quantities.
